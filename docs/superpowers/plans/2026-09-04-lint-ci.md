# Lint CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a GitHub Actions workflow that genuinely lints the repository's Django, React, and Express source code and can be run automatically or manually.

**Architecture:** Keep the course template's independent Python and JavaScript jobs, but make both jobs check out the repository and invoke package-local, reproducible lint commands. Flake8 checks the Django tree with the existing codebase's 100-character convention; React uses its existing Create React App ESLint configuration, while Express uses pinned JSHint with an explicit Node/ECMAScript environment.

**Tech Stack:** GitHub Actions, Python 3.12, Flake8 7.3.0, Node.js 24, ESLint via react-scripts 5.0.1, JSHint 2.13.6, npm lockfiles

**Spec:** `docs/superpowers/specs/2026-09-04-lint-ci-design.md`

## Global Constraints

- Preserve all application routes, payloads, runtime dependencies, and runtime
  behavior.
- Do not add deployment jobs or upgrade unrelated dependencies.
- The workflow name is `Lint Code`.
- Trigger on pushes and pull requests for `main` and `master`, and support `workflow_dispatch`.
- Grant the workflow only `contents: read` repository permission.
- Use a 100-character Flake8 line limit.
- Use package-local JavaScript lint tools and committed lockfiles; do not install an unpinned global linter.
- Do not push changes to GitHub as part of implementation.

### Task 2: GitHub Actions lint workflow

**Files:**
- Create: `.github/workflows/main.yml`

**Interfaces:**
- Consumes: `npm run lint` from `server/frontend` and `server/database`, Python files under `server`, and the two committed npm lockfiles.
- Produces: the GitHub Actions workflow `Lint Code`, with jobs named `lint_python` and `lint_js` and a manual `workflow_dispatch` trigger.

- [ ] **Step 1: Confirm the workflow is absent**

Run:

```bash
test -f .github/workflows/main.yml
```

Expected: exit status 1 because the workflow does not exist.

- [ ] **Step 2: Create the workflow**

Create `.github/workflows/main.yml` with:

```yaml
name: Lint Code

on:
  push:
    branches: [main, master]
  pull_request:
    branches: [main, master]
  workflow_dispatch:

permissions:
  contents: read

jobs:
  lint_python:
    name: Lint Python Files
    runs-on: ubuntu-latest
    steps:
      - name: Check out repository
        uses: actions/checkout@v7

      - name: Set up Python
        uses: actions/setup-python@v7
        with:
          python-version: "3.12"

      - name: Install Flake8
        run: python -m pip install flake8==7.3.0

      - name: Lint Python files
        run: >-
          flake8 server
          --max-line-length=100
          --extend-exclude=server/.venv,server/frontend/node_modules,server/database/node_modules,server/djangoapp/migrations

  lint_js:
    name: Lint JavaScript Files
    runs-on: ubuntu-latest
    steps:
      - name: Check out repository
        uses: actions/checkout@v7

      - name: Set up Node.js
        uses: actions/setup-node@v7
        with:
          node-version: "24"
          package-manager-cache: false

      - name: Install React dependencies
        run: npm ci --prefix server/frontend

      - name: Lint React files
        run: npm run lint --prefix server/frontend

      - name: Install Express dependencies
        run: npm ci --prefix server/database

      - name: Lint Express files
        run: npm run lint --prefix server/database
```

- [ ] **Step 3: Validate workflow YAML structure**

Run:

```bash
ruby -e 'require "yaml"; document = YAML.safe_load_file(".github/workflows/main.yml", aliases: true); abort "missing jobs" unless document["jobs"].keys.sort == %w[lint_js lint_python]'
```

Expected: exit 0 with no output.
